# 首屏结论卡（First-Screen Card）

本文件定义**首屏结论卡**的固定格式。首屏结论卡是这套 workflow 的运行时唯一接入口：面对任何新案件，默认先产出一张首屏结论卡，而不是先写长正文、先列补件清单或先做银行 / 产品匹配。

语言风格总纲见 `narrative-style-guide.md`（一线人格声明 + 一线词表 / 禁词表）；判断口径见 `rm-scan-chain.md`（九步扫描链）。本文件只管首屏卡的格式与写法。

## 一、首屏卡固定只回答四件事

首屏卡固定四位，不增不减、不换顺序。报告小标题固定用以下中文定稿标题（不自造问答式标签，见 `narrative-style-guide.md` 第七节硬规则 8）；英文为系统字段名，只活在 JSON 合同里（合同见 `output-spec.md`）：

| # | 报告标题 | 内容 | 系统字段 |
| --- | --- | --- | --- |
| 1 | 这个户能不能做 | 四档 + 一句话理由；有缺料附"待核查资料" | `client_tier` |
| 2 | 瑕疵与调整 | 瑕疵一句话定性 + 怎么调整 / 怎么优化基本面；硬门瑕疵必须带调整方向判断 | `blocker_and_remedy` |
| 3 | 空间提示 | 销贷比口径的额度空间粗估 | `capacity_hint` |
| 4 | 下一步 | 推进动作最多两条，具体到"找客户要什么、问什么" | `next_actions` |

（"报告标题 ↔ 系统字段"两列复制自 `narrative-style-guide.md` 第五节，改动须同步；"内容"列为本文件补充。）

## 二、四位各自怎么写

### 第 1 问 · 这个户能不能做（`client_tier`）

写法要求：

- 四档之一 + 一句话理由。判定规则见 `rm-scan-chain.md` 第四节，定稿话术见 `narrative-style-guide.md` 第五节：**优质户，优先跟 / 正常户，按流程推 / 有机会，看看 / 放弃**。
- 理由一句话说清这个档怎么来的：硬门过没过、卡点几个、豁免有没有生效。
- **初判不悬置**：关键材料缺失照常按现有资料给初判分档，缺的列入"待核查资料"——写清缺什么、核到什么可能改档。不写"材料不够暂不判断"。
- 分档结论直接写，不另加"本结论仅供参考"式免责句（见 `narrative-style-guide.md` 第七节硬规则 9）。

一线话术样例：

> 正常户，按流程推。行业、征信两关都过了，卡点就一个开票和他说的营收对不上，能调。待核查资料：企业征信原件——拿到没硬伤就维持这档。

### 第 2 问 · 瑕疵与调整（`blocker_and_remedy`）

写法要求：

- 瑕疵一句话定性，说清卡在哪，不铺开明细（明细归附录）。
- **每处瑕疵都要给出怎么调整 / 怎么优化基本面**；硬门瑕疵必须带调整方向判断：补材料 / 调表述 / 换实控人 / 换主体，四个方向逐一掂量。**硬门瑕疵没有可行调整方向才落"放弃"档**——落"放弃"前必须写清：瑕疵是什么、掂量过哪些调整方向、为什么走不通（硬门调整方向自查见 `rm-scan-chain.md` 第六节）。
- 每个卡点后面必须跟得上动作，不允许只定性不给路（见 `narrative-style-guide.md` 第三节）。
- 没有卡点的户，这一位写"没硬卡点"，可以补一句最值得盯的事项或直接点亮点。
- 硬门出局的户也照常产出完整首屏卡与正文——其余步骤按已有材料扫描（规则见 `output-spec.md` 九步扫描判断节），调整方向一旦成立（如换实控人），判断可直接复活，不用重做。

一线话术样例：

> 卡在实控人征信有当前逾期。先问一句：实控人能不能换？换得了这单还能做，换不了再放弃。
>
> 卡在开票只有他说的三成。这样调：补材料，让客户拿流水或合同说清差额从哪来。

### 第 3 问 · 空间提示（`capacity_hint`）

写法要求：

- 销贷比口径的额度空间粗估：**年销售 X、现有负债 Y、按 ≤50% 通用口径的空间判断**（口径与提示线细则见 `rm-scan-chain.md` 第八节）。
- 年销售采用流水营收口径时，先写清统计期间，再固定分列：**对公账户营收 X、私人账户营收 Y（个人银行卡 A、微信 B）、合计可识别营收 Z**。不得只给合计数。
- 优质户注明可放宽：有标签或好行业时点明豁免依据（统一豁免规则见 `rm-scan-chain.md` 第七节）。
- 只做空间粗估，**禁止"XX 行能批 XX 万"式承诺额度 / 期限**。
- 年销售或现有负债口径缺 → 写明空间算不出来，缺口列入待核查资料。

一线话术样例：

> 近 12 个月合计可识别营收 3000 万，其中对公账户 1800 万、私人账户 1200 万（个人银行卡 700 万、微信 500 万）。现有负债加这次要的合计 1200 万，销贷比四成，空间还有。

### 第 4 问 · 下一步（`next_actions`）

写法要求：

- 推进动作**最多两条**，具体到"找客户要什么、问什么"。写成动作，不写成补件清单；每条写清拿到 / 问到之后判断会怎么变（改档、定卡点、定空间）。
- 立场是帮客户过关，不是盘问：写「让客户把上下游合同拿两份来，差额就能说清」，不写「要求客户解释差额原因」（见 `narrative-style-guide.md` 第四节）。

两条动作的排序规则：

1. **第一条压在最大卡点上**：最大卡点是什么，第一条就去要能解开它的材料、问能解开它的问题。
2. **第二条补承载或证据侧**：企业债务结构、企业征信、经营辅助证据（现有流水能不能当经营回款用）等关键缺口。

**第二条的例外**：若企业征信缺失、且债务负担对本案明显偏重（已有债务多、个人月供 / 担保责任明显），第二条改为**先把企业征信原件要到、把企业负债结构摸清**——这时候负债摸不清比"流水能不能采信"更先影响判断。

不允许的排法：

- 第一条去要与最大卡点无关的通用材料。
- 两条压同一块（如都在要流水），浪费一次推进机会。
- 把次级明细（信用卡、查询、按揭逐笔）排进两条动作。

一线话术样例：

> 下一步就两条：先让客户拿流水或合同说清开票差额从哪来；再把企业征信原件要到手，负债结构摸清了空间才算得准。

## 三、不能写什么

首屏卡内禁止出现：

- 银行推荐、产品推荐
- 承诺式额度 / 期限（"XX 行能批 XX 万"式）——**允许**销贷比口径的空间粗估，第 3 问就是干这个的
- 修复方案、养单方案、过件包装路径
- 信用卡、查询、账单、担保链等次要明细（归附录）
- 预检补件语气（"请补 X、Y、Z"式清单）——第 4 问写成推进动作，不写成清单
- 禁词表词汇（见 `narrative-style-guide.md` 第二节；命中 = 压测一票否决）

## 四、几处数字对不上时首屏怎么落

（本节说的是自述、开票、纳税、流水等多来源数字对不上的情形——系统层旧称含禁词表词汇，报告文字不得使用该旧称；处理流程仍以 `conflict-handling.md` 为准，挂载位置见 `rm-scan-chain.md` 第九节。）

- 若数字对不上就是最大卡点 → 写进第 2 问：「卡在票上开的和他嘴上说的对不上，差额得让客户说清从哪来」。
- 若差额不改变分档 → 不在首屏展开，落附录 / 系统层。
- 首屏不展开逐笔明细，只写差额改不改判断、下一步找客户要什么。

## 五、首屏卡与正文、附录的关系

- 首屏卡是**入口与结论摘要**：四问一眼可读。
- 正文是首屏卡的展开，按九步扫描结构组织（**5 章**：客户情况 / 九步扫描判断 / 瑕疵与调整 / 下一步推进动作 / 材料调整与优化建议，见 `output-spec.md`）。
- 附录表承载明细。
- 三者不矛盾：首屏卡的分档、卡点、空间必须与正文、附录一致；沟通汇总表（`comm-summary-table.md`）同样继承这套底座判断，对外档位结论必须一致。
