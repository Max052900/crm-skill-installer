# Reroute Rules

> **定位说明（2026-07）**：本文件规则语义不变；文中"Current Path Status""路径受阻"为系统层旧称，报告层落位见下文第四节括注与 `first-screen-card.md`。

本文件定义第四个核心动作：**原路径不通时，别把全案一起判死。**

## 一、原则

原路径不通 ≠ 全案否决。客户经理要分清"某条路不通"和"这个客户不能做"。

## 二、触发条件（保留备选路径）

原路径受阻时，满足以下情形 → **不把全案判死，保留备选路径空间**：

1. 主矛盾只否决了某条**具体路径**（某类产品、某种授信结构、某条承接路径），而主体、经营证据本身仍成立。
2. 仍存在另一条由经营证据 / 主体支持的可走路径。

## 三、不适用 reroute 的情形

以下不是 reroute，而是全案否决方向，不保留备选路径：

- 主矛盾命中红线。
- 主体真实性本身不成立（如疑似空壳、借壳 / 通道）。
- 经营真实性本身不成立。

## 四、输出落点

reroute 情形下：

- Current Path Status 写「路径受阻」（系统层旧称；报告层落位：第 2 问写明这条路走不通的原因与调整方向掂量，第 4 问给转向动作），并明确说明：原路径受阻**不等于**全案否决。
- 正文说明：原路径为何不通；是否仍有备选路径方向。
- 受当前阶段边界约束，**不输出**具体银行 / 产品 / 额度 / 期限；只表达"路径仍有空间"或"需换承接路径再看"。

## 五、与其他规则的关系

- 与 `clarify-rules.md` 区分：clarify 是"路没看清"，reroute 是"路看清了、但这条不通"。
- 与 `path-status-rules.md` 衔接：reroute 判断结果落在「路径受阻」状态。
- 与 `priority-rules.md` 衔接：主矛盾否决的是"某条具体路径"还是"全案"，决定走 reroute 还是走否决。
