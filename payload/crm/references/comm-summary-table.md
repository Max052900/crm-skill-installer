# 沟通汇总表（Comm Summary Table）

本文件定义第三输出档位**沟通汇总表**的固定格式与写法规则。系统字段合同见 `output-spec.md` 第九节；语言风格遵守 `narrative-style-guide.md`（一线词表 / 禁词表）。

## 一、定位与用途

用户是**融资顾问，坐在客户和银行客户经理中间**，这张表两头都要能用：对客户，说清还差什么材料、为什么要；对银行客户经理，给一份可直接转述的**客户信息汇总**——给事实、让银行客户经理自己判断，不做倾向性包装。

用户原话：「做完判断后和材料分析后，给我一张简洁的汇总表，目的是：便于我和在客户和客户经理间进行沟通」。

一页三分区，做完判断和材料分析后随手可发，不是另一份报告。

## 二、触发词

用户说以下任一即产出本表：**「出汇总表」「沟通汇总表」**。用户泛指"给我一张表"时先确认是否指沟通汇总表，确认后再产出。

## 三、定稿模板

```markdown
【客户沟通汇总表 · <企业名>】                    <日期>

■ 客户情况
| 项 | 内容 |
| --- | --- |
| 主体 | <企业名、成立年限、实控人> |
| 主营业务 | <做什么生意、卖给谁、账期特点> |
| 分档 | <四档之一 + 待核查资料（如有）> |
| 亮点 | <征信/资产/行业/标签等> |
| 卡点 | <一句话 + 调整方向> |
| 营收分拆 | <统计期间；对公营收（对公账户）；私人账营收（个人银行卡、微信）；合计可识别营收> |
| 空间 | <销贷比口径空间提示> |

■ 跟客户要的
| 材料/动作 | 为什么要 | 紧急度 |
| --- | --- | --- |
| ... | ... | 立刻/本周/报单前 |

■ 给客户经理的信息汇总
| 项 | 内容 |
| --- | --- |
| 基本面 | <主营业务、客群画像、经营年限；有存货库存信息则加上> |
| 营收 | <对公 X；私帐 Y（银行卡 A、微信 B）；结息 Z——结息少于 100 元写"没什么结息"> |
| 负债 | <法人 X；配偶 Y；企业 Z（分列，不合并）> |
```

三分区固定，不增不减：**客户情况**（给自己和两头对齐基本盘）、**跟客户要的**（对客户）、**给客户经理的信息汇总**（对银行客户经理）。紧急度只用三档：立刻 / 本周 / 报单前。

## 四、写法规则

1. **用词按用户口述习惯**：说「客户情况」，不说「户情速览」；全表用一线词表的口语词（这个户 / 能做 / 卡在 XX / 瑕疵怎么调 / 有抓手），零禁词（见 `narrative-style-guide.md` 第二节）。
2. **第三区是客户信息汇总，不是推荐理由**：给事实、让银行客户经理自己判断——与"瑕疵不主动列"同源：不是隐瞒瑕疵，而是不做倾向性包装。三行按推单开口顺序固定：基本面（主营业务、客群画像、经营年限；有存货库存信息则加上）→ 营收（对公 / 私帐（银行卡、微信）/ 结息——数字难看也照报，结息少于 100 元写"没什么结息"，轻描淡写收掉、不展开辩解）→ 负债（法人 / 配偶 / 企业按人分列，不合并）。缺材料的项如实写"未提供"。进度承诺不生成——那是用户自己把握的话术，表里不写"几天能批""下周报单"这类话。
3. **结论与底座判断一致**：对外四档位（完整预检稿 / 客户沟通版 / 沟通汇总表 / 资料澄清清单）共用同一套底座判断。前三个档位间，分档档位词、卡点定性、空间结论的**语义与数字不得改写**；表格槽位允许压缩表述。资料澄清清单不出现档位与判断结论，其一致性检查点=资料与待核查资料一致、问题与瑕疵 / 观察项对应、零行话、无档位泄漏（见 `client-checklist-output.md`）。多卡点时，"卡点"行只写最先影响推进的一个（含调整方向），其余卡点通过"跟客户要的"区体现。
4. **放弃户与有机会户也出表**：放弃户仍产出本表，第三区照出信息汇总（事实不因档位变），但在第三区顶部加一行「暂不推报 + 原因（调整方向确认走不通）」；有机会户第三区照常出，信息如实。
5. **营收必须分账户说**：只要使用流水营收数字，“营收分拆”行必须同时写“对公营收（对公账户）”“私人账营收”及“合计可识别营收”；私人账营收括号注明个人银行卡和微信各自金额。缺材料写“未提供”，确认无营收才写 0。
