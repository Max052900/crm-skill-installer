# Corporate Relationship Manager Capability Model

本文件蒸馏“对公客户经理”的完整能力。`corporate-precheck` 当前已经实现能力 1/2 的预检合同；后续扩展必须沿着本能力模型补齐，而不是零散增加话术或银行产品规则。

## 一句话定义

对公客户经理不是“找一个能批的产品”，而是把一家企业还原成可被银行判断的经营主体、现金流主体、信用主体和风险主体，再把客户需求翻译成合规、可审、可跟进的信贷路径。

## 核心心法

先还原经营，再判断主体，再看现金流，再看债务结构，再组织材料，最后才谈产品路径。

必须始终区分四件事：

1. 客户想要什么
2. 企业真实发生了什么
3. 银行能用什么证据相信它
4. 这笔业务发放后怎么安全退出

## 完整能力地图

### 0. 合规和边界能力

目标：知道哪些事不能做，哪些表达不能说，哪些资料不能乱用。

必须具备：

- 识别个人敏感信息、企业敏感资料、征信和流水数据的处理边界
- 坚持授权、最小必要、脱敏和用途限定
- 不承诺包过，不承诺确定额度，不包装虚假材料
- 区分“解释真实情况”和“制造虚假资质”
- 把银行政策、监管要求和客户沟通话术分开

官方锚点：

- 《中华人民共和国个人信息保护法》：个人信息处理应有明确合理目的，并采取对个人权益影响最小的方式
- 《流动资金贷款管理办法》：流动资金贷款用途必须明确、合法，并按合同约定检查和监督资金使用

### 1. 客户发现和入口判断

目标：判断这是不是值得继续看的客户，而不是被客户的问题带着跑。

必须识别：

- 真实经营客户、短期周转客户、债务重组客户、停损客户、不可做客户
- 客户是经营问题、资料问题、结构问题、时点问题、政策问题，还是意愿问题
- 客户当前最痛的是额度、成本、期限、续贷、抽贷、查询、流水、税票、负债还是资料说不清

产物：

- 客户入口标签
- 初始优先级
- 首轮资料范围

### 2. 主体和关系还原能力

目标：先搞清楚谁借钱、谁经营、谁还钱、谁担责。

必须还原：

- 法人、股东、实控人、配偶、关联企业、上下游、担保人
- 申请主体、经营主体、开票主体、流水主体、资产主体是否一致
- 企业成立时间、变更、股权、控制权、关联交易和关联担保

典型矛盾：

- 实际经营人不是法人
- 流水主体和申请主体不一致
- 开票主体和收款主体不一致
- 用关联企业承接收入或负债

产物：

- 主体关系图
- 申请主体可用性判断
- 主体错配追问

### 3. 经营真实性和行业理解能力

目标：判断企业是否真实经营，以及银行能否看懂它的行业逻辑。

必须判断：

- 行业粗路由：优先、可做、谨慎、限制
- 经营模式：贸易、生产、餐饮、服务、工程、平台、门店、经销、供应链
- 收入来源、毛利逻辑、回款周期、上下游集中度、季节性
- 税票、水母、流水、合同和订单之间是否能互相解释

产物：

- 经营画像
- 经营可见度等级
- 经营异常/空壳风险判断

### 4. 财务和现金流分析能力

目标：判断企业有没有承载能力，以及还款来源是否能解释。

必须看：

- 资产负债表：资产质量、负债规模、权益、应收、存货、货币资金
- 利润表：收入、毛利、净利、费用、利润真实性
- 流水：真实收款、对手方、集中度、回款周期、异常流入流出
- 税票：开票趋势、纳税趋势、上下游、断崖或异常增长
- 周转：采购、销售、库存、账期、资金缺口

产物：

- 现金流还款来源判断
- 周转资金缺口判断
- 承载能力降级项

### 5. 征信和债务结构能力

目标：不是简单看“好不好”，而是看债务结构是否还能解释。

必须看：

- 个人征信：贷款、信用卡、查询、逾期、担保、共借、公共记录
- 企业征信：贷款、授信、票据、担保、司法、欠税、风险记录
- 债务结构：短贷长用、到期集中、先息后本堆叠、网贷高息、担保链
- 查询结构：贷款审批、贷后管理、担保资格、法人高管资信、信用卡审批

产物：

- 债务树
- 查询压力解释
- 到期压力表
- 红线和可解释瑕疵区分

### 6. 资金需求和用途判断能力

目标：判断客户的钱到底要解决什么问题，期限和用途是否匹配。

必须判断：

- 日常经营周转、采购备货、应收垫资、设备投入、装修改造、续贷过桥、债务置换、短期拆借
- 资金用途是否合法、明确、可被证明
- 需求金额是否和经营周转缺口匹配
- 期限是否和回款周期匹配

产物：

- 资金用途说明
- 周转缺口解释
- 不匹配风险提示

### 7. 产品路径和授信结构能力

目标：把客户情况翻译成可审的授信结构，但不虚构银行政策。

必须掌握的路径类型：

- 流动资金贷款
- 经营性个人贷款
- 小微企业信用类产品
- 抵押经营贷
- 票据、保理、应收账款、供应链金融
- 续贷、无还本续贷、展期或重组边界
- 保证、抵押、质押、担保公司、核心企业增信

必须约束：

- 没有明确银行政策矩阵时，只能输出路径类型和待验证政策点
- 不能凭经验编造银行准入、利率、额度、期限
- 产品路径必须回到主体、经营、现金流、债务和用途证据

产物：

- 路径候选
- 政策待验证清单
- 授信结构草案

### 8. 材料组织和授信叙事能力

目标：把真实材料组织成银行看得懂的逻辑。

必须做到：

- 区分正文、附录、底稿、敏感材料
- 把客户自述改成证据链，而不是故事
- 把瑕疵改成原因、影响、补证和还款来源
- 把经营、资金用途、还款来源、风险缓释串成一条线

产物：

- 客户经理预检正文
- 授信叙事草稿
- 附录表
- 资料补齐清单

### 9. 沟通和异议处理能力

目标：让客户、渠道和银行都知道下一步该做什么。

必须处理：

- 客户只问额度和利率
- 客户不愿提供材料
- 渠道催进度
- 银行要求补充解释
- 征信瑕疵、查询多、流水少、负债重、主体不一致等异议

产物：

- 客户首轮沟通提纲
- 渠道交接话术
- 银行补充说明要点
- 预期管理话术

### 10. 流程推进和节点管理能力

目标：把一个客户从初筛推进到放款或停损，不丢节点。

必须管理：

- 资料收集
- 授权和隐私
- 预审
- 进件
- 补件
- 审批条件
- 合同签署
- 放款
- 资金用途检查
- 还款和续贷提醒

产物：

- 进度表
- 下一步行动清单
- 阻塞项
- 责任人和截止时间

### 11. 贷后和关系经营能力

目标：业务不是放款结束，而是持续风险和转介绍关系。

必须跟踪：

- 资金用途是否偏离
- 流水、税票、经营是否下滑
- 到期和续贷窗口
- 客户新增负债和查询
- 转介绍时机
- 案例复盘和脱敏沉淀

产物：

- 贷后观察表
- 续贷窗口提醒
- 风险预警
- 脱敏案例复盘
- 转介绍话术

## 能力成熟度分层

| Level | 能力 | 输出 |
| --- | --- | --- |
| L1 | 材料读取和槽位归一 | 材料分类、槽位表、缺口 |
| L2 | 预检判断 | 核心矛盾、首轮追问、正文和附录 |
| L3 | 路径诊断 | 路径候选、政策待验证点、资料策略 |
| L4 | 授信叙事 | 授信故事线、风险解释、材料包结构 |
| L5 | 流程推进 | 节点管理、补件、沟通、审批条件跟进 |
| L6 | 贷后经营 | 资金用途、还款、续贷、风险预警、转介绍 |

当前 `corporate-precheck` 已覆盖 L1-L2 的合同层。要做到完整对公客户经理，需要继续补 L3-L6 的知识资产和验证样本。

## 六张图模型

每个客户最终都要能画出六张图：

1. 主体关系图：谁申请、谁经营、谁控制、谁担责
2. 经营事实图：行业、客户、供应商、订单、税票、流水
3. 债务结构图：个人债、企业债、担保、到期、成本
4. 资金用途图：钱从哪里缺、用到哪里、多久回来
5. 还款来源图：经营现金流、应收回款、资产处置、其他来源
6. 材料路径图：已有什么、缺什么、谁补、补完解决哪个矛盾

## 判断顺序

1. 是否合规和可接触
2. 主体是否能成立
3. 经营是否真实可见
4. 债务结构是否还能解释
5. 资金用途是否明确合法
6. 还款来源是否能闭环
7. 是否有合适路径类型
8. 需要哪些材料支撑
9. 下一步由谁做什么

## 禁止伪客户经理行为

- 只看产品，不看经营
- 只看额度，不看还款来源
- 只看征信瑕疵，不看主体和资金用途
- 只列补件清单，不说明补件要解决哪个矛盾
- 用“查询多”“负债高”替代完整债务结构判断
- 直接输出银行、产品、额度、期限而没有政策依据
- 为了过审制造、包装或暗示虚假材料
