# 模式层节点协议 v1

本文件是**模式层（能力 3 + 能力 4）的总纲骨架**。它把 11 个节点统一定位、定义接口、标注落地状态，作为后续逐节点填充的地基。

> **重要边界：** 本文件是骨架，不是实现。涉及客户经理专业口径的节点，本文件只占位、不擅自固化业务规则——专业口径必须先与用户讨论确认（见文末「专业口径占位清单」）。

---

## 一、模式层定位

四层能力图：

| 层 | 能力 | 性质 | 状态 |
| --- | --- | --- | --- |
| 1 看懂客户 | 材料理解 | 底座层 | 已稳定可交付 |
| 2 看懂卡点 | 预审判断 | 底座层 | 已稳定可交付 |
| 3 判断路径 | 授信路径判断 | **模式层** | 部分隐含落地 |
| 4 推动案件 | 推进 / 叙事 / 沟通 | **模式层** | 多为半成品或空白 |

- **能力 3 不是"银行匹配 / 产品推荐 / 额度期限建议 / 修单清单"**，而是**路径判断层**：在底座看懂客户、看懂卡点之后，判断案件当前应沿哪条授信路径推进，路径不顺时判断补证据继续、切备选、暂停、还是先澄清。
- **能力 4 不是"修单话术"**，而是**推进 / 叙事 / 沟通层**：判断怎么把这条路推下去、按什么顺序、怎么和客户开口、怎么把客户讲成一个授信能过的故事。

---

## 二、模式层与底座的接口

**模式层只吃底座的整理结果，不重读原始材料。**

模式层的统一输入 = 底座产出的三层输出 + 系统层：

- 首屏结论卡（client_tier / blocker_and_remedy / capacity_hint / next_actions；系统层旧称：path_type / primary_contradiction / current_path_status / next_two_verifications）
- 九步扫描正文五章（系统层旧称：客户经理式正文五段）
- 附录六表
- 系统层（material_index / slot_records / issues / secondary_tracks / suppressed_noise / stage_gate_result）

模式层不得回到原始 PDF / Excel / 图片重新抽取——底座没整理出来的信息，模式层也不能凭空补。

---

## 三、统一约束（所有节点必须遵守）

1. **只吃底座整理结果**——不重读原始材料、不补底座没产出的事实。
2. **每个节点都必须有失败态**——信息不足时有明确降级出口。
3. **失败优先降级，不硬猜**——判不了就标"待确认 / 待评估"，不编结论。
4. **关键输出必须解释 why**——路径、阻断、推进价值、叙事都要给依据。
5. **不越权到银行 / 产品 / 额度 / 期限 / 修单 / 养单层**——继承底座边界。
6. **延续筛选 + 辅导定位，不做审批**——模式层是帮客户经理把案件推下去，不是审批拒绝（见 `narrative-style-guide.md` 第六节）。

## 四、能力 3 — 路径判断层（5 节点）

### 3-1 路径类型识别

- **职责：** 判断案件当前应沿哪条授信路径推进（这是什么路）。
- **输入：** 底座 path_type、主体槽位、经营证据。
- **输出：** 当前主路径类型 + 判路依据。
- **失败态：** 主体 / 经营 / 借款承接不清 → 路径未明，转 clarify。
- **落地状态：** ✅ **已落地** — `path-type-rules.md`（5 类路径枚举）。
- **专业口径占位：** 无（已确认）。

### 3-2 路径阻断判断

- **职责：** 判断当前路径上有没有阻断点，且每个阻断是"硬阻断"还是"可缓释"。
- **输入：** 底座主矛盾、冲突记录、红线信号、征信 / 债务槽位。
- **输出：** 阻断点清单，每个标记「硬阻断 / 可缓释」+ why。
- **失败态：** 阻断性质不明 → 标「待确认阻断」，不硬判死全案。
- **落地状态：** 🔶 **半成品** — 散在 `reroute-rules.md`「不适用 reroute 的情形」（红线 / 真实性否决）+ `priority-rules.md` 的 redline 排序。缺系统的"阻断点类型表 + 硬阻断 vs 可缓释判定"。
- **专业口径占位：** ⚠️ 哪些算硬阻断（红线 / 真实性否决 / 主体不成立）、哪些算可缓释（征信瑕疵 / 查询多 / 短期逾期 / 单口径冲突）——需用户确认清单。

### 3-3 路径切换判断

- **职责：** 原路径不通时，判断是补证据继续、切备选路径、暂停推进、还是先做结构澄清。
- **输入：** 3-2 阻断判断 + 备选路径空间。
- **输出：** 切换决策（继续补 / 切换 / 暂停 / 澄清）+ 备选路径。
- **失败态：** 无备选且原路径阻断 → 不判死全案，标「待客户补充关键证据」。
- **落地状态：** ✅ **大部分已落地** — `reroute-rules.md`（保留备选路径、不判死全案）。
- **专业口径占位：** 无（核心逻辑已确认；具体备选路径枚举待后续补）。

### 3-4 补件价值排序

- **职责：** 在该补的材料里，判断哪个补件最能抬路径（不是按材料类型，是按对路径的抬升价值）。
- **输入：** 底座缺口清单 + 3-1 路径 + 3-2 阻断。
- **输出：** 补件按「对路径的抬升价值」排序。
- **失败态：** 缺口太多无法全排 → 只标最高价值 1-2 项。
- **落地状态：** 🔶 **半成品** — `priority-rules.md` 首轮追问 + `first-screen-card.md` 第 4 问排序规则。缺独立的"补件价值模型"。
- **专业口径占位：** ⚠️ 补件价值怎么排（解锁路径 > 抬升承载 > 补强叙事？）——需用户确认。

### 3-5 推进价值判断

- **职责：** 判断这个客户**值不值得**继续花精力推（不是"能不能做"，是"值不值得做"）。
- **输入：** 底座主体 / 经营 / 承载 + 3-1~3-4。
- **输出：** 推进价值档（高 / 中 / 低 / 暂放）+ why。
- **失败态：** 信息不足判不了价值 → 标「价值待评估」，先按继续看处理。
- **落地状态：** ❌ **空白**。
- **专业口径占位：** ⚠️⚠️ 推进价值怎么判（什么客户优先推、什么客户先放、值不值的标准是什么）——需用户**大量讨论**。这是客户经理每天都在做的核心决策。

## 五、能力 4 — 推进 / 叙事 / 沟通层（6 节点）

### 4-1 推进顺序判断

- **职责：** 判断案件整体推进的先后顺序（先做什么、后做什么）。
- **输入：** 3-4 补件价值 + 3-5 推进价值。
- **输出：** 推进步骤序列。
- **失败态：** 顺序依赖不明 → 只给第一步。
- **落地状态：** 🔶 **半成品** — 首屏第 4 问排序规则（系统层旧称 Next Two Verifications 排序），但那是"先验证什么"，不是案件整体推进顺序。
- **专业口径占位：** 与 4-6 阶段划分绑定，一并讨论。

### 4-2 追问节奏判断

- **职责：** 判断多轮追问的节奏（这轮问什么、客户回了之后下轮问什么）。
- **输入：** 4-1 推进顺序 + 底座首轮追问。
- **输出：** 分轮追问计划。
- **失败态：** 客户响应不可预期 → 只规划当前轮。
- **落地状态：** 🔶 **半成品** — 首轮最多 2 问（`priority-rules.md`），但没有多轮节奏。
- **专业口径占位：** ⚠️ 追问节奏（一次问几个合适、问太多吓跑客户 vs 问太少效率低的平衡）——需用户确认。

### 4-3 客户沟通口径

- **职责：** 判断对客户怎么开口（哪些直说、哪些委婉、哪些先不说）。
- **输入：** 3-2 阻断 + 4-2 追问。
- **输出：** 对客户的沟通话术口径。
- **失败态：** 敏感问题不确定怎么说 → 标「建议当面沟通」。
- **落地状态：** 🔶 **半成品** — `narrative-style-guide.md`「不是审批员」是报告语气，不是"对客户怎么开口"的沟通口径。
- **专业口径占位：** ⚠️⚠️ 哪些能直说、哪些要委婉（征信问题 / 负债问题 / 经营存疑怎么跟客户提）——需用户**大量讨论**。

### 4-4 案件叙事组织

- **职责：** 把客户讲成一个授信能过的故事（经营逻辑 + 资金用途 + 还款来源 + 瑕疵解释串成一条线）。
- **输入：** 底座全部 + 3-x 路径判断。
- **输出：** 授信叙事草稿骨架。
- **失败态：** 经营逻辑不成立 → 不硬编故事，回 3-5 重判推进价值。
- **落地状态：** ❌ **基本空白**。
- **专业口径占位：** ⚠️⚠️ 授信叙事怎么讲（经营逻辑 / 用途合理性 / 还款来源 / 瑕疵缓释的标准讲法）——需用户**大量讨论**。这是客户经理最值钱的能力。

### 4-5 收资组织

- **职责：** 把该收的材料组织成清单 + 顺序，给客户经理去收。
- **输入：** 3-4 补件价值 + 4-1 推进顺序。
- **输出：** 收资清单（分批次 + 优先级）。
- **失败态：** 清单太长 → 分批，先给第一批。
- **落地状态：** 🔶 **半成品** — 第 5 章「材料调整与优化建议」覆盖一部分，但没有系统的收资清单 + 收资顺序。
- **专业口径占位：** 与 3-4 补件价值绑定，一并讨论。

### 4-6 阶段推进与交接

- **职责：** 判断案件当前在哪个推进阶段，下一阶段交接给谁 / 做什么。
- **输入：** 4-1~4-5 全部。
- **输出：** 当前阶段 + 下一阶段动作 + 交接点。
- **失败态：** 阶段不清 → 标「待明确推进阶段」。
- **落地状态：** ❌ **空白**（`stage-gates.md` 是内部验收门，不是客户案件的推进阶段）。
- **专业口径占位：** ⚠️ 客户经理的案件推进阶段怎么分（初判 → 收资 → 叙事 → 报送 → 跟进…）——需用户确认。

## 八、专业口径占位清单（待与用户逐项确认）

以下是模式层填充时必须先和用户讨论的专业判断点，本文件**只占位、不固化**：

1. **3-2 阻断分类**：哪些是硬阻断、哪些是可缓释。
2. **3-4 / 4-5 补件价值排序**：补件价值的排序标准（解锁路径 / 抬升承载 / 补强叙事）。
3. **3-5 推进价值判断**（核心）：什么客户优先推、什么客户先放、值不值的标准。
4. **4-2 追问节奏**：一次问几个、多轮节奏怎么把握。
5. **4-3 客户沟通口径**：哪些能直说、哪些要委婉。
6. **4-4 案件叙事**（最值钱）：授信叙事的标准讲法。
7. **4-6 推进阶段划分**：案件推进阶段怎么分。

## 九、模式层当前不实现什么

继承底座边界，模式层当前不做：

- 银行匹配、具体银行政策矩阵
- 产品推荐、额度建议、期限建议、利率
- 修单 / 养单 / 过件包装
- 没有政策来源时输出具体银行内部政策

模式层的"路径"是**授信路径类型**（经营贷 / 抵押 / 信用 / 供应链 / 票据 / 续贷 / 停损等大类方向），不是具体某家银行的某个产品。
