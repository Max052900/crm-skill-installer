# Clarify Rules

> **定位说明（2026-07）**：本文件规则语义不变；文中"首屏判断卡第 3 问 Current Path Status""待 clarify""Next Two Verifications"为系统层旧称——新首屏结论卡的第 3 问是"空间提示"，澄清动作在报告层落位为第 2 问"瑕疵与调整"的待澄清表述与第 4 问"下一步"的追问动作（见 `first-screen-card.md`）；"待 clarify"报告层写"待澄清"。

本文件定义首屏判断卡第 3 问 Current Path Status 中**"待 clarify"状态**的触发条件。

clarify 是四个核心动作之一：**路没看清时先澄清，不直接往下推判断。**

## 一、触发条件

命中以下任一条 → 路径状态置「待 clarify」，Path Type 多半落「路径未明」，**不得直接给出继续 / 不继续的路径结论**：

### 1. 主体关系不清

- **1-a　承接主体不明**：谁是实际借款人、谁实际承接还款责任说不清。
- **1-b　实控人与股权结构显著背离**：实际控制人不持股，或持股比例与控制权明显不符。命中 1-b 必须先 clarify 实控来源——是代持、借名，还是受托经营——才能认定判断主体。

### 2. 经营事实自相矛盾

经营口径之间矛盾到形不成经营口径锚点（自述、报表、流水互相打架且无法取舍出一个起点）。

### 3. 借款用途与承接主体对不上

钱给谁用、谁还，说不通；用途与承接主体之间存在结构性错配。

## 二、判断主体认定原则

clarify 之所以必要，是因为"判断主体"不能按形式层直接认定。

- **借款主体（授信主体）** = 企业法人本身，固定，不需认定。
- **判断主体** = 客户经理要去还原征信、品行、经营能力、还款意愿、资产的那个自然人。原则是**实质重于形式**：认实际控制人 + 实际借款人 + 实际经营决策者，而不是默认认法人代表或大股东。

当实控人与股权 / 法人身份背离时，先 clarify、后认定，不能跳过。

## 三、示例

实控人 a（实际借款人、不持股）、法人 b（持股 10%）、大股东 c（持股 90%，不实控、不用款）：

- 判断主体按实质应认 a。
- 但 a 实控却不持股、c 持股 90% 却不实控 → 命中触发条件 1-b → 路径状态「待 clarify」。
- 必须先问清 a 的实控来源：
  - c 是 a 的代持人 → 穿透代持，a 既是实控也是真实股东。
  - c 是真实大股东、a 受托经营 → a 借 c 的公司融资，主体错配风险高。
  - 纯借壳 / 通道 → 红线方向。
- 三种答案路径完全不同，所以必须 clarify 后才能定 Path Type 与主矛盾。

## 四、clarify 与首轮追问

clarify 命中时，Next Two Verifications 的两个问题优先用于澄清上述不清项，而不是去验证次级矛盾。

## 五、clarify 之后

- clarify 得到答案 → 重新判 Path Type 与 `primary_contradiction`，状态可从「待 clarify」转入「待验证」或其他。
- clarify 长期得不到答案 → 路径停滞或转谨慎（见 `path-status-rules.md`）。
