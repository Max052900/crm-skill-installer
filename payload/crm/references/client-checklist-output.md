# 资料澄清清单输出档位（客户直发版）

对外档位中的**第四档位**（对外档位总览见 `output-spec.md`）。**直接发给客户**用——判断完可能的问题后，把"客户缺什么资料、存在什么问题需要澄清"总结成两张清单发给客户（用户口径见 `rm-voice-corpus.md` 场景 9：「现在是对客户的了，你判断了可能的问题，要总结客户缺什么资料，存在什么问题需要澄清」）。

与第二档位**客户沟通版**（`client-comm-output.md`）的分工：客户沟通版带判断结论，给客户经理**面谈客户**用；本档位不带判断、纯两张清单，**直接发客户**。两档都保留（用户口径「都留」）。

## 一、定位

- 给谁看：客户本人，可直接转发。
- 内容只有两张清单：①需要补的资料（列：资料 | 说明）②需要说清楚的问题（列：问题 | 背景）。就这两件事，不是另一份报告。
- 底座判断（首屏结论卡 + 九步扫描正文五章 + 附录 6 表）照常先跑；本档位从底座的待核查资料与瑕疵 / 观察项中提取，转译成客户听得懂的话。

## 二、触发词

用户说以下任一即产出本清单：**「出资料清单」「澄清清单」「给客户的资料清单」**。默认仍是完整预检稿；本档位要显式触发。

## 三、定稿模板

```markdown
# <企业名> · 需要补充的资料与需要说明的问题（<日期>）

> 底稿出处：<企业名> CRM 完整预检（<日期>）。本清单对客户使用：只列资料和问题，不含判断结论与档位。

## 一、需要补的资料

| # | 资料 | 说明 |
|---|---|---|
| 1 | <要什么材料，客户话，关键词可加粗>（<期间范围，如"近 12 个月"）> | <怎么准备 / 范围提示，如"找代账会计出""哪张卡有经营收款就拉哪张"> |
| 2 | ... | ... |

## 二、需要说清楚的问题

| # | 问题 | 背景 |
|---|---|---|
| 1 | <问题，客户话，具体到事实> | <为什么问，如"银行会问到""车登记在商行名下"> |
| 2 | ... | ... |
```

- 表格化、编号、每条一行；语气平实（"有就说，没有不勉强""说一声即可"式），不加急、不施压。
- 顶部"底稿出处"引注行供用户自己追溯用，**不得出现档位词**；直发客户时可整行删去。

## 四、五条规则（硬约束）

1. **不带档位 / 判断结论**——四档词（优质户 / 正常户 / 有机会 / 放弃）、结论句、分档理由是内部专用，本清单一律不出现。
2. **不带销售话术**——报价预期、利率沟通、成交推动、进度承诺属用户本人的销售范畴，清单里不写。
3. **不带说服铺垫**——要材料就直接列清单，不写"为了帮您争取更好条件"式铺垫（用户口径见 `rm-voice-corpus.md` 场景 6：要材料不存在说服环节）。
4. **零行话**——不出现水母 / 销贷比 / 征信硬门 / 待核查资料等内部词，用客户听得懂的话（说"税务零申报""征信报告缺最后两页"，不说"水母异常""销贷比缺口"）。
5. **澄清问题必须带背景**——每条问题的"背景"列写清为什么问（如"银行会问到""车登记在商行名下"），客户看得懂来意，但不是被审问。

## 五、与底座的一致性要求

本档位与其他三个对外档位共用同一套底座判断，**同一底座判断不得多头口径**：

- **需要补的资料 ↔ 底座待核查资料**：来自 `client_tier.pending_verification_materials`，并合并下一步推进动作、材料调整与优化建议中要客户补的材料，去重后转译成客户话。不得出现底座没有的新要求，也不得漏掉底座列明的关键待核查资料。
- **需要说清楚的问题 ↔ 底座瑕疵 / 观察项**：每条问题必须能在底座的瑕疵与调整（`blockers`）或系统层次级记录（`secondary_tracks`）中找到对应项，语义一致，只是转译成客户话；不得自造底座没判断过的问题。

验收检查点（阶段门用，见 `stage-gates.md` / `stage-gate-checklist.md`）：资料与待核查资料一致、问题与瑕疵 / 观察项对应、零行话、无档位泄漏。
