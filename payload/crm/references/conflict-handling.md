# Conflict Handling

本文件定义口径冲突处理。目标是把"文字说明先作经营口径锚点、再追差额来源、判断差额是否改变路径"固化成可执行流程，避免机械按最低数字覆盖。

本文件是 `input-spec.md` 的延伸：`input-spec.md` 负责材料分类与可信度排序，本文件负责**多来源冲突如何处理**。

## 一、核心原则

冲突不得被抹平。两个来源同字段不一致时：

1. 保留所有值、各自来源、冲突记录，不静默覆盖、不删除低优先级来源。
2. **文字说明先作经营口径锚点**：客户自述 / 信息采集表 / 聊天摘要给出的经营口径（如自报实际销售额）先作为"经营事实锚点"，不被报表或开票数字直接推翻。
3. 再追差额来源：找出锚点口径与证据材料数字之间的差额，追问差额从哪里来。
4. 最后判断差额是否改变路径：差额能被解释 → 留附录或次级轨道；差额改变承载或经营真实性判断 → 升级为路径压力。

## 二、为什么文字说明先作锚点

低优先级来源（自述、销售口径）证据等级最低，但它承载的是**经营口径**——客户对自己生意规模的描述。

- 若直接用开票额、报表数字覆盖自报销售额，会把"开票率低""未入账经营"这类正常现象误判成"经营造假"。
- 正确做法：先认下文字口径作为"客户声称的经营事实"，再用证据材料去验证 / 追差额，而不是反过来用最低数字直接定性。

这不等于相信自述。锚点只是判断**起点**，是否成立仍要证据验证。

## 三、典型冲突场景与处理

| 冲突 | 处理 |
| --- | --- |
| 自报实际销售额 > 开票额 | 文字口径作锚点；差额可能是未开票经营，追流水 / 回单 / 水母是否支撑实际销售口径 |
| 财报收入 与 水母开票趋势不一致 | 两值并存；按证据优先级（财报 > 水母）记录，追口径期间与并表范围差异 |
| 个人征信负债 与 自述负债不一致 | 以征信为准，自述差额进冲突记录；若自述明显低报，提升为主体诚信观察点 |
| 摘要口径企业负债 与 企业征信原件缺失 | 摘要值标 `inferred` 并降级，不得当作确定结论；追企业征信原件 |
| 流水回款 与 开票规模不匹配 | 两值并存；判断是回款周期、对手方结构问题，还是经营真实性问题 |

## 四、经营规模多口径冲突

当客户自述月营收、年实际销售、开票额、纳税额、流水营收之间互相冲突时，按本节处理。流水营收必须先按“对公账户营收 / 私人账户营收 / 合计可识别营收”完成分拆和去重，再参与比较；不得拿账户总流入直接与销售额比较。

### 成立条件（必读，先于升级规则）

「经营规模多口径冲突」**必须至少存在两个以上可读经营口径才能成立**。

- 可读经营口径包括：客户自述月营收 / 年实际销售（信息采集表或聊天摘要里写下的数字）、开票额、纳税额、已经分拆去重的流水营收（对公账户营收、私人账户营收、合计可识别营收）、税票报告里的开票或纳税口径等。
- 若材料中**经营口径来源数量 < 2**（如只有个人征信 + 尚未拆出经营回款的个人流水 + 一张企业截图），**不得认定为「多口径冲突」**。此时应记录为「经营口径缺失 / 不可验证」，按 `input-spec.md` 材料可读性降级为 `degraded_readable` 或 `blocked`。个人 / 微信流水若已拆出可识别经营回款，可作为一个流水营收口径计数。
- 不允许把企业类目、经营异常截图等非数字口径当作"经营口径"。
- **不得凭样板描述凭空补出"应该有的口径"再去算差额。** 样板演示的是材料完整时的判断，材料稀疏时不能反向倒推。

成立条件不满足时，主矛盾仍可落 `operation_reality_visibility`，但措辞是「经营口径无可读来源」而不是「多口径冲突」。稀疏材料版样板见 `examples/sample-c-sparse-material-visibility.md`。

### 多口径并列，不取单一数字

把月营收、年销售、开票、纳税、合计可识别流水营收当作五个并列口径，全部保留，不挑一个当真值、也不按最低值覆盖。流水口径内必须同时保留对公账户营收与私人账户营收的分拆；私人账户营收再保留个人银行卡与微信分项。文字自述（月营收 / 年销售）按本文件第一、二节仍先作经营口径锚点。

### 升级规则

任意两个口径之间差额 ÷ 较高口径 > **10%**，且差额无可核经营证据解释时 → 升级为 `operation_reality_visibility` 路径压力，作为 `primary_contradiction` 候选。可核经营证据既包括对公账户材料，也包括已经识别、去重的个人银行卡或微信经营回款。

常见冲突信号：

- 开票额与自述销售额差距大（开票率异常高或异常低）。
- 纳税额与开票额、销售额不成比例（如开票数千万、纳税仅数万）。
- 自述月营收换算的年规模与自述年销售对不上。
- 合计可识别流水营收与自述经营规模对不上；或流水只能看到总流入，尚未拆出可识别经营回款（见 `priority-rules.md` 个人 / 微信营收识别规则）。

### 落点

升级后，主矛盾写 `operation_reality_visibility`，首屏卡 Primary Contradiction 用路径影响语言写“经营规模有多个口径但都未被可核经营回款坐实，这先于债务等问题压住路径”（系统层旧称；报告层落位见 first-screen-card.md 第四节：冲突压住判断时写进第 2 问卡点，缺数时列待核查资料）。逐笔口径数字进附录 / 系统层，不在正文铺开。

## 五、差额是否升级为路径压力

差额处理分三档：

- **可解释、不改路径** → 进附录或 `secondary_tracks`，不进正文。
- **暂不可解释、需验证** → 进首轮验证点（Next Two Verifications），路径状态保持"待验证"。（系统层旧称；报告层落位见 first-screen-card.md 第四节：冲突压住判断时写进第 2 问卡点，缺数时列待核查资料）
- **升级为路径压力** → 升级为 `primary_contradiction` 候选，进入 `priority-rules.md` 排序。

### 升级判定规则

**硬阈值：** 差额绝对值 ÷ 自报经营口径锚点 > **10%** → 直接升级为路径压力。

**兜底（差额 ≤ 10% 也升级）：** 即使差额未超 10%，命中任一条仍升级：

- 差额完全追不到来源（无流水 / 回单 / 合同 / 水母可解释）。
- 差额直接改变承载判断（如导致真实偿债能力算不清）。

**未触发升级的差额：** 可解释且不改路径 → 附录 / `secondary_tracks`；暂不可解释但可验证 → 进 Next Two Verifications，路径状态保持"待验证"。（系统层旧称；报告层落位见 first-screen-card.md 第四节：冲突压住判断时写进第 2 问卡点，缺数时列待核查资料）

## 六、冲突在输出层如何落

- 首屏判断卡：若冲突就是主矛盾，写进 Primary Contradiction；否则不在首屏展开。（系统层旧称；报告层落位见 first-screen-card.md 第四节：冲突压住判断时写进第 2 问卡点，缺数时列待核查资料）
- 正文：只写"差额是否改变路径"，不展开逐笔明细。
- 附录 / 系统层：保留所有冲突值、来源、证据引用，记入 `issues` 与冲突记录。
