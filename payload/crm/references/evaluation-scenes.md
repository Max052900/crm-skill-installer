# Evaluation Scenes

本文件定义离线压测与回归用的场景清单。

## 关键边界

这些场景**只用于离线压测和回归**，检验 workflow 节点是否跑偏。

**不是运行时客户类型框。** 运行时禁止先把真实客户往场景里套再判断——那样会退化成样本驱动的预审系统。运行时判断必须直接基于当前案件的主体、经营、征信、财报、水母、流水、主矛盾、路径阻断和推进价值推理。

## 8 类压测场景

用于检验 workflow 是否会滑回"预审员逻辑"：

| # | 场景 | 检验什么 |
| --- | --- | --- |
| 1 | 强主体 + 小噪音 | 噪音压制：小问题是否被压到附录，不抢正文主线 |
| 2 | 主体一般 + 经营证据强 | 3-1 路径类型识别：是否先看经营证据能否抬路径，而非先验压低（系统层等价判定；报告层对应：分档理由句） |
| 3 | 主体 / 经营承接不清 | clarify：是否先澄清，而非硬推判断 |
| 4 | 关键证据一补可能反转 | 路径状态：升级 / 停滞条件是否说清（系统层等价判定；报告层对应：改档条件） |
| 5 | 内部判断未稳但必须沟通 | 沟通边界：中间态是否保留、不越权承诺 |
| 6 | 当前主路径被阻断但备选路径存在 | reroute：是否保留备选，而非判死全案 |
| 7 | 信息很多但没有主线 | 主矛盾唯一性：是否收敛成唯一核心矛盾（系统层等价判定；报告层对应：卡点主线） |
| 8 | 客户很急但暂不宜推进 | 推进价值判断：是否被客户情绪带偏推进顺序 |

## 流水营收分拆专项回归

所有涉及个人银行卡或微信收款的样本，额外检查以下边界，不另设客户类型：

- 对公账户经营回款 180 万、个人银行卡经营回款 70 万、微信经营回款 50 万时，输出必须写：对公账户营收 180 万；私人账户营收 120 万（个人银行卡 70 万、微信 50 万）；合计可识别营收 300 万。
- 微信收款 50 万后全部提现到个人银行卡时，合计仍只增加 50 万，不得把微信提现重复计算。
- 个人银行卡总流入 200 万，其中借款 60 万、内部划转 30 万、可识别经营回款 70 万、待核实 40 万时，只把 70 万计入私人账户营收；其余分别列为已剔除或待核实。
- 某渠道材料缺失时填“未提供”或系统层 `null`；确认没有该渠道营收时才填 0。
- 样本期不足 3 个月时，只报样本期分拆金额，不年化推全年。

## 用法约束

- 场景标签只进 system 层 / 回归记录，不进首屏卡、正文、附录。
- 真实案件不得标注"属于场景 X"。
- A / B / C / D 等字母只是压测 / 回归场景槽位，不得用作运行时客户分类。
