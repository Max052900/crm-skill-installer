# Stage-Gate Checklist

每次用真实样本验证时复制本清单。

## A Material Readability

- [ ] 材料全部登记 `material_id`
- [ ] 材料分类为 intake / personal_credit / corporate_credit / financial_statement / shuimu / flow_support / other / unknown
- [ ] 未知或不可读材料被保留
- [ ] 主体可确认，或明确 `blocked`

## B Consistency Readability

- [ ] 同字段多来源数字冲突被记录为 issue
- [ ] 冲突值全部保留，未被静默抹平（静默覆盖来源即失败）
- [ ] 证据优先级被记录
- [ ] 决策为 block / downgrade / appendix / follow-up 之一

## C Priority Readability（系统层）

- [ ] 系统层只有一个 `primary_contradiction`（内部字段，不进报告文字）
- [ ] 其他候选进入 `secondary_tracks`
- [ ] 噪音没有参与 tie-break
- [ ] 没有银行、产品、承诺式额度 / 期限、修复或养单逻辑

## D Next-Action Usability

- [ ] 推进动作不超过 2 条
- [ ] 第一条压最大卡点，第二条补承载或证据侧
- [ ] 每条写清找客户要什么、问什么、拿到后判断怎么变
- [ ] 没有泛化补件清单

## E Output Usability

首屏检查：

- [ ] 首屏结论卡四问齐全：这个户能不能做（四档 + 一句话理由，缺料附待核查资料）/ 瑕疵与调整 / 空间提示 / 下一步

正文检查：

- [ ] 正文五章齐全：客户情况 / 九步扫描判断 / 瑕疵与调整 / 下一步推进动作 / 材料调整与优化建议
- [ ] 九步扫描判断九步都有结论态（过 | 卡 | 亮点 | 未提供 | 出局；「出局」仅第 2、3 步硬门可用）
- [ ] 下一步推进动作最多两条
- [ ] 材料调整与优化建议 1-5 条，辅导式语气（客户应该补 / 调整 / 优化什么），不夹审批式拒绝词
- [ ] 第 5 章与下一步推进动作不机械重复——可以围绕同一关键材料，但视角必须从"立刻问什么"转成"客户如何准备 / 调整 / 优化"，且至少包含更宽的辅导建议

结论检查：

- [ ] 结论只用四档 + 待核查资料话术（优质户，优先跟 / 正常户，按流程推 / 有机会，看看 / 放弃）
- [ ] 系统层映射字段（旧三枚举 `current_precheck_decision.decision`）在系统层记录中保留
- [ ] 初判不悬置：关键材料缺失仍给分档 + 待核查资料（写清缺什么、核到什么可能改档）
- [ ] 每处硬门瑕疵带调整方向判断（补材料 / 调表述 / 换实控人 / 换主体）；确认无可行调整方向才得落"放弃"档
- [ ] 输出层零禁词（禁词表见 `narrative-style-guide.md` 第二节）
- [ ] 对外档位结论一致（若产出客户沟通版 / 沟通汇总表）：分档、卡点、空间三处一致
- [ ] 资料澄清清单（若产出）：资料与待核查资料一致、问题与瑕疵 / 观察项对应、零行话、无档位与判断结论泄漏

明细与降噪：

- [ ] 附录六表存在
- [ ] 信用卡、查询、账单、担保链、次要会计明细默认在附录
- [ ] 短周期（不足 3 个月）流水未被年化推全年规模
- [ ] 多来源数字冲突未被静默抹平

## F Sample Hardening

- [ ] 样本类别已标注（强样本 / 谨慎行业 / 主体错配 / 稀疏材料）
- [ ] 隐私状态已标注
- [ ] 验证结果已记录
- [ ] 缺样本时记录缺口，不用假样本替代
