# Path Status Rules

> **定位说明（2026-07）**：本文件自 2026-07 起为**系统层内部判断规则**，不再作为报告主线；判断语义全部保留，供系统层字段与回归等价判定用。报告层的结论语言见 `narrative-style-guide.md` 第五节（四档 + 待核查资料）。**对应关系**：路径状态四元素（状态 / 状态原因 / 升级条件 / 停滞条件）的语义转译进首屏结论卡**第 1 问"这个户能不能做"的理由句**与**第 2 问"瑕疵与调整"的写法要求**（见 `first-screen-card.md`）——状态与状态原因对应第 1 问的分档理由，升级条件对应调整方向与待核查资料的"核到什么可能改档"，停滞 / 转谨慎条件对应第 2 问调整方向掂量后的走向。下文提及"首屏判断卡第 3 问"等旧报告落位的表述，仅作历史对照。

本文件定义旧首屏判断卡第 3 问 **Current Path Status（这条路现在停在哪）** 的判断规则（现为系统层内部字段）。

目标：把输出从 `need_key_info` 式预检补件语气，升级为"当前路径处于什么状态、为何如此、补到后如何升级、补不到会停在哪里"的路径状态语言。（该目标现由首屏第 1、2 问的写法要求承接，见顶部定位说明。）

## 一、状态必须含四个表达元素

任何 Current Path Status 输出必须同时写清：

1. **状态** —— 当前路径处于什么状态
2. **状态原因** —— 为什么处于这个状态
3. **升级条件** —— 补到什么、验证到什么，路径会往前走
4. **停滞 / 转谨慎条件** —— 补不到、或验证结果为负时，路径会停在哪 / 转向哪

只写"缺什么材料"不算合格状态输出，必须写"这条路现在处于什么状态、补到后会怎样变化"。

> **报告层落位**：四元素不再作为独立报告段落出现。报告里对应的写法是——第 1 问理由句写清"这个档怎么来的"（状态 + 原因），待核查资料写清"核到什么可能改档"（升级条件），第 2 问写清"救不了会怎样"（停滞 / 转谨慎条件）。写法要求见 `first-screen-card.md`。

## 二、状态集合

> 路径类型见 `path-type-rules.md`；状态描述的是"该路径当前推进到哪一步"。

| 状态 | 含义 |
| --- | --- |
| 待验证 | 仍在原路径上补关键证据继续看；主体 / 经营不构成阻断，缺口是可验证的具体证据 |
| 待 clarify | 主体 / 经营 / 借款承接本身没看清，须先澄清才能继续推判断 |
| 可继续 | 关键证据已坐实，路径可进入下一步正式判断 |
| 转谨慎 | 关键验证结果为负，或经营证据持续补不到，路径下调 |
| 路径受阻 | 原路径不通；是否保留备选路径见 reroute 规则（第二批） |

> "待 clarify" 状态的触发条件见 `clarify-rules.md`；"路径受阻"状态下是否保留备选路径见 `reroute-rules.md`。

## 三、状态升级与停滞

- 升级：升级条件被满足 → 状态向"可继续"推进。
- 停滞：升级条件长期不被满足 → 状态停在原处，并在输出中说明停在哪。
- 转向：关键验证结果为负 → 状态转"转谨慎"或"路径受阻"，**但不得据此把全案一起判死**（reroute 留备选空间，第二批细化）。

## 四、与决策词表的关系

（旧三枚举现仅作系统层映射与历史对照，报告层结论语言为四档 + 待核查资料，映射唯一出处见 `narrative-style-guide.md` 第五节。）

Current Path Status 是路径语言层；它最终仍映射到 `priority-rules.md` 的决策词表：

- 待验证 / 待 clarify → `need_key_info`
- 可继续 → `continue_precheck`
- 转谨慎 / 路径受阻 → `need_key_info` 或 `not_recommended_for_precheck`

（本表仅历史对照；与 `narrative-style-guide.md` 第五节的四档映射冲突时，以第五节为准。）

状态语言负责"说清这条路停在哪"，决策词负责"给系统一个结论标签"，两者必须一致。

## 五、表达模板：私人账户营收暂时拆不出来

当案件提供了个人银行卡或微信流水，但借款、内部划转、微信提现与经营收款尚未拆开时（见 `priority-rules.md` 个人 / 微信营收识别规则），Current Path Status 套用以下模板：

- **状态：** 待验证。
- **状态原因：** 已有个人 / 微信流水可见，但目前只能看到总流入，尚未拆出可识别经营回款，也未完成微信提现与账户互转去重。
- **升级条件：** 客户标注经营收款，或补到订单、合同、发票 / 回款对应关系后，拆出“对公账户营收 + 私人账户营收”，可识别部分计入企业实际营收，路径升级为“可继续”。
- **停滞 / 转谨慎条件：** 持续无法拆出经营回款，或合计可识别营收与自述规模严重背离，路径停在“待验证”或转“谨慎”。

要点：私人账户收款不是排除项；无法识别经营背景、无法去重才是问题。报告不得写“个人流水不能算营收”，应写“已识别的部分计入私人账户营收，未识别部分暂不计入”。
