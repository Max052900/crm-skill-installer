# Roadmap

本路线图把对公客户经理能力拆成可交付阶段。每个阶段都必须有样本验证，不能只写规则。

## Phase 1: Read And Normalize

Status: implemented as contract.

能力：

- 材料分类
- 槽位抽取
- 缺失降级
- 多来源冲突保留

验证：

- 至少 5 个真实脱敏材料包
- 覆盖 Word、PDF、Excel、图片或扫描件

## Phase 2: Precheck And First Questions

Status: implemented as contract, one real small sample tested.

能力：

- 唯一核心矛盾
- 噪音压制
- 最多两个首轮问题
- 正文加附录

验证：

- 强经营案例
- 查询多案例
- 负债重案例
- 主体错配案例
- 经营可见度弱案例

## Phase 3: Path Judgment（路径判断层 = 能力 3）

Status: partially implemented（3-1 已落地、3-3 大部分落地，详见 `mode-layer-node-protocol.md`）。

> **定位纠偏：** 能力 3 是**路径判断层**，不是"银行匹配 / 银行政策矩阵"。判断案件沿哪条授信路径类型推进、路径不顺时如何处置，不落到具体某家银行的产品。模式层 11 节点的完整骨架见 `mode-layer-node-protocol.md`。

能力（对应模式层节点）：

- 3-1 路径类型识别（区分经营贷、商户贷、抵押、信用、供应链、票据、续贷、停损等大类方向）
- 3-2 路径阻断判断（硬阻断 vs 可缓释）
- 3-3 路径切换判断（补证据 / 切备选 / 暂停 / 澄清）
- 3-4 补件价值排序
- 3-5 推进价值判断

所需资产：

- 路径类型规则（已有 `path-type-rules.md`）
- 阻断分类口径、补件价值口径、推进价值口径（待与用户确认，见节点协议第八节）
- 失败案例库

禁止：

- 银行政策矩阵 / 具体银行 / 产品 / 额度 / 期限（不属于路径判断层）

## Phase 4: Advance / Narrative / Communication（推进 / 叙事 / 沟通层 = 能力 4）

Status: partially implemented（4-1/4-2/4-3/4-5 半成品，4-4/4-6 空白，详见 `mode-layer-node-protocol.md`）。

> **定位：** 能力 4 是**推进 / 叙事 / 沟通层**，不是"修单话术"。判断怎么把路推下去、按什么顺序、怎么和客户开口、怎么把客户讲成授信能过的故事。模式层 11 节点的完整骨架见 `mode-layer-node-protocol.md`。

能力（对应模式层节点）：

- 4-1 推进顺序判断
- 4-2 追问节奏判断
- 4-3 客户沟通口径
- 4-4 案件叙事组织（授信叙事：经营逻辑 / 用途 / 还款来源 / 瑕疵缓释串成一条线）
- 4-5 收资组织
- 4-6 阶段推进与交接

所需资产：

- 授信叙事模板、瑕疵说明模板、经营情况说明模板
- 追问节奏口径、客户沟通口径、推进阶段划分（待与用户确认，见节点协议第八节）

## Phase 5: Process Follow-Up

Status: not implemented.

能力：

- 资料补齐节点
- 渠道/客户/银行三方跟进
- 补件回应
- 审批条件追踪
- 放款前检查

所需资产：

- 进度表模板
- 跟进话术库
- 审批条件清单

## Phase 6: Post-Loan And Relationship

Status: not implemented.

能力：

- 贷后资金用途观察
- 月度经营数据监控
- 到期续贷提醒
- 风险预警
- 老客户转介绍
- 脱敏案例复盘

所需资产：

- 贷后观察表
- 续贷节点表
- 转介绍话术
- 案例复盘模板

## Upgrade Rule

每次升级只推进一个阶段，并补齐：

- 输入样本
- 输出格式
- 禁止事项
- 验证标准
- 至少一个真实脱敏样本结果

不允许跳过样本验证直接增加复杂规则。
