# Evaluation Scorecard

本文件定义单样本压测判分表。**30 分制：6 个维度 × 5 分**，外加一票否决项。

## 6 个评分维度（每项 0-5 分）

| 维度 | 5 分标准 | 失分信号 |
| --- | --- | --- |
| 判断主线感 | 先判"这个户能不能做"，按九步扫描链顺序推进：前 3 步快筛给初判分档，后 6 步算"能做多大、怎么做成"（主线见 `rm-scan-chain.md`） | 退回问题罗列、平铺补件，不按九步扫描组织判断 |
| 硬门 vs 可调卡点区分 | 能区分两道硬门（行业限制类 / 征信不良）与普通卡点；硬门出局前先走调整方向自查，调不回来才落"放弃" | 把能调的卡点直接判成放弃，或把硬门触发当普通卡点放过 |
| 推进顺序 | 推进动作最多两条：第一条压最大卡点，第二条补承载或证据侧，顺序合理 | 通用补件清单、被客户情绪带偏、两条动作压同一块 |
| 沟通边界 | 只做销贷比口径的空间粗估，不越权承诺 | 越权到银行 / 产品 / 承诺式额度期限 / 修单养单 |
| 待核查资料运用 | 初判不悬置：材料缺失照常按现有资料给分档，缺的显式列入"待核查资料"，写清缺什么、核到什么可能改档 | 悬置分档（"材料不够暂不判断"）、硬猜结论不列待核查资料、静默抹平多来源数字冲突 |
| 一线味 | 用词像一线：零禁词、口述习惯词、像真客户经理说话；立场是业绩视角：先找能做的理由和调整方向，不是先找问题；调整意识——瑕疵先想怎么调再想放弃 | 审批腔 / 风控腔 / 分析师术语、悬置判断（"材料不够暂不判断"）、卡点无调整方向判断、报告像填表系统输出 |

## 分档

| 总分 | 分档 |
| --- | --- |
| 27-30 | 像一线客户经理 |
| 22-26 | 基本对路，但还不稳 |
| < 22 | 不合格（仍偏预审 / 材料整理） |

## 材料阻断 / Gate A 失败时的处理

样本材料缺失、不可读、或路径未挂载，导致无法形成有效盲跑输出时，**不计入 30 分制**：

- 总分记为 `N/A（材料阻断）`，不写 `0/30`。0/30 表示运行时跑出了输出但全维度失分，与材料缺失是两件事，不可混用。
- 各维度都标 `N/A`，不写 0。
- 一票否决记为「未评估」。
- 分档记为「未通过 — 非有效回归样本」。
- 暴露问题写清阻断原因（材料路径未挂载 / 路径为空 / 关键文件不可读等）。
- 不据此修订规则；先把材料挂载好，再重新跑该样本。

材料阻断属于回归流程问题，不是 skill 规则问题。本 scorecard 只给"运行时跑出了输出"的样本打分。

## 一票否决项

命中任一条即不通过，无论总分多少：

- 输出层命中禁词表词汇（禁词表见 `narrative-style-guide.md` 第二节）
- 越权输出银行 / 产品 / 修单 / 养单，或承诺式额度 / 期限（"XX 行能批 XX 万"式）——销贷比口径的空间粗估（`capacity_hint`）是允许的，不算越权
- 退化成补件清单或材料流水账
- 无依据把全案判死（含：硬门瑕疵未做调整方向判断就落"放弃"档）
- 红线漏判
- 抹平多来源数字冲突（静默覆盖来源）
- 使用流水营收却未拆分对公账户营收与私人账户营收，或把微信提现 / 账户互转重复计入营收

- 一票否决：未触发 | 触发（哪条）

- 暴露问题：

- 建议修正：
