# Input Spec

> 本文件规则语义不变；文中"核心矛盾判断""路径判断""首轮验证"等为系统层旧称，报告层语言见 `narrative-style-guide.md` 第五节。

本文件定义能力 1/2 的输入分类和降级规则。目标是先把材料读清楚，不提前进入银行或产品匹配。

## 材料分类

### 进件口径和主体自述

包括客户经理转述、渠道交接表、聊天记录摘要、客户自填表、申请诉求、资金用途、企业和个人基础情况。

作用：

- 建立主体、企业、申请诉求、经营年限、行业、城市和需求金额等基础槽位
- 暂存销售口径和客户自述，但证据优先级最低
- 帮助生成首轮追问

### 个人征信

包括个人征信报告、征信摘要、贷款和信用卡明细、查询记录、逾期记录、担保和共同借款信息。

作用：

- 判断个人负债结构、信用瑕疵、查询压力和主体承载能力
- 识别是否存在红线或主体错配
- 给正文或附录提供个人信用证据

### 企业征信

包括企业信用报告、企业贷款、授信、担保、司法和风险记录。

作用：

- 判断企业债务结构、授信占用、对外担保和企业层面风险
- 与财报、水母和主体自述互相校验

### 财务报表

包括资产负债表、利润表、现金流量表、科目余额表、审计报告、纳税申报财务口径。

作用：

- 判断资产负债、收入利润、应收应付、存货、权益和表内承载能力
- 和企业征信、水母、流水互相校验经营真实性和规模一致性

### 水母报告

包括水母数据、税票趋势、开票、纳税、上下游、工商和经营画像类报告。

作用：

- 判断经营画像、税票趋势、客户/供应商集中度和真实经营迹象
- 辅助识别空壳、断崖、异常增长或行业偏好风险

### 流水辅助材料

包括银行流水、收款码流水、对账单、平台流水、合同回款记录。

作用：

- 辅助判断真实收款、经营可见度、回款周期和现金流压力
- 在没有财报或水母时提供可见度，但不能替代正式报表

企业对公流水、个人银行卡流水、微信流水必须分开归集。个人银行卡和微信中的可识别经营回款可以计入企业实际营收，但报告必须拆成“对公账户营收”和“私人账户营收（个人银行卡 + 微信）”；同一笔微信提现、账户互转或平台与银行重复记录不得重复计算。借款、退款、理财赎回、还款、内部划转及无法说明经营背景的入账不计营收，完整认定规则见 `priority-rules.md`。

### 其他材料

包括营业执照、产权、租赁合同、订单、合同、发票影像、说明书、授权书等。

作用：

- 作为证据补强或附件，不默认进入正文
- 只有改变主体、经营、资产、合规或路径判断时才提升为正文依据

## 缺失降级规则

### 缺个人征信

个人信用压力、红线和查询判断降级为 `not_enough_to_calculate`。不得凭客户自述判断个人征信干净。

### 缺企业征信

企业债务结构、企业授信、企业担保和企业风险判断降级。可以继续看主体和经营事实，但必须标注企业信用可读性不足。

### 缺财务报表

资产负债、表内承载能力、收入利润和资产质量判断降级。不得输出资产负债能力的确定性结论。

### 缺水母

业务画像、税票趋势、开票和上下游集中度判断降级。可以用流水或合同辅助判断可见度，但必须标注税票侧不可读。

### 缺流水

收款稳定性、回款周期和实际现金流可见度降级。不得把水母或客户自述等同于真实流水。

### 只有自述或销售口径

只允许生成材料缺口和首轮追问，不允许给出继续预检的确定性判断。

## 材料可信度

证据优先级从高到低：

1. 正式个人或企业征信报告
2. 正式财务报表或审计材料
3. 水母或同类经营数据报告
4. 银行流水、平台流水、合同和发票等业务证据
5. 客户自述、销售口径、聊天摘要

同一字段多来源冲突时，按上述顺序决定处理结果，但不得删除低优先级来源；低优先级来源仍进入冲突记录或附录。

## 最小输入可用性

能力 1/2 可以在材料不完整时运行，但输出必须区分：

- `readable`：关键输入足够，可进入核心矛盾判断
- `degraded_readable`：可以继续，但必须说明降级项
- `blocked`：只有口径或关键主体缺失，不能进入矛盾判断

最低可运行组合：

- 进件口径 + 任一正式证据材料：可做降级预检
- 进件口径 + 个人征信 + 企业经营证据：可做初步矛盾判断
- 进件口径 + 个人征信 + 企业征信 + 财报或水母：可做较完整能力 1/2 预检

### 稀疏材料组合（无进件口径 / 无经营规模数字）

只有个人征信 + 个人流水 + 一张企业基础截图、且个人流水尚未拆出可识别经营回款、无其他可读经营规模口径（月营收 / 年销售 / 开票 / 纳税 / 对公流水统计 / 私人账户可识别营收均缺失）：

- 状态：`degraded_readable`。主体可读、个人侧可读，但经营规模、收入、税票、回款均不可确定。
- 可进入路径判断（路径多半为「经营可见度待验证路径」），但**不能形成确定性经营规模冲突**——见 `conflict-handling.md` 第四节「成立条件」。
- 主矛盾仍落 `operation_reality_visibility`，但措辞是「经营口径无可读来源」，不是「多口径冲突」。
- 首轮验证先让客户标注现有个人流水中的经营收款；仍拆不出数字时，再索取**经营口径来源本身**（信息采集表 / 客户自述经营规模 / 企业征信 / 税票 任一份）。不得因为缺对公流水就跳过现有私人账户经营回款。
- 样板见 `examples/sample-c-sparse-material-visibility.md`。
